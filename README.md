# unigig

The freelance marketplace built exclusively for college students — hire trusted student talent, or earn money on your own schedule.

This repository is a **monorepo** containing a TanStack Start (React + SSR) frontend and an Express + PostgreSQL backend, designed from day one so it can be deployed online with minimal changes.

---

## Tech stack

### Frontend (`client/`)
- **React 19** + **TanStack Start** (file-based router with SSR via h3)
- **Vite 7** for dev/build
- **Tailwind CSS 4** + **shadcn/ui** (Radix primitives)
- **TanStack Query** (React Query) for data fetching, caching, and mutations
- **Axios** for HTTP, with JWT attach + auto-refresh interceptors
- **Lucide** icons

### Backend (`server/`)
- **Node.js 20+** + **Express 4** + **TypeScript**
- **Prisma 5** ORM with **PostgreSQL 16**
- **JWT** access tokens (15 min) + rotating **refresh tokens** (30 days, DB-tracked, reuse-detection)
- **bcrypt** password hashing (12 rounds)
- **Zod** for request validation
- **Helmet** + **express-rate-limit** for security
- **Multer** for file uploads (storage interface swappable: local ↔ S3/R2)
- **google-auth-library** — Google OAuth scaffolded, feature-flagged off until you turn it on

### Infrastructure
- **Docker Compose** for local Postgres (persistent volume)
- **npm workspaces** for monorepo orchestration
- **concurrently** to run client + server together

## First-time setup

**Prerequisites:** Node ≥ 20, npm ≥ 10, Docker Desktop running.

```bash
# 1. Install all workspace dependencies
npm install

# 2. Copy env templates (the *.development files are already committed for local use)
cp client/.env.example client/.env.development      # optional, already present
cp server/.env.example server/.env.development      # optional, already present

# 3. One-shot: start Postgres, run migrations, seed
npm run setup
```

That gets you:
- A running Postgres container (`unigig-postgres`) on `localhost:5432` with a persistent named volume (`unigig-pgdata`)
- All Prisma migrations applied
- 15 users, 10 jobs, 6 proposals seeded — every user's password is `password123`

## Running locally

```bash
npm run dev
```

This single command:
1. Brings Postgres up (no-op if already running) and waits for it to be healthy
2. Runs pending migrations + regenerates the Prisma client
3. Starts the **API** at http://localhost:4000 and the **client** at http://localhost:3000 in parallel (`concurrently`)

You'll see colored logs labeled `server` (blue) and `client` (magenta). Hit Ctrl-C once to stop both.

### Try it out
- Log in at http://localhost:3000/login with `alex@bu.edu` / `password123` (or any seeded address)
- Browse `/hire` (freelancers from Postgres), `/work` (jobs), `/profile` (edit + save persists)
- Sign up at `/signup` — verification email is written to `server/dev-emails/` AND printed to the server console with the verify link. Click the link, then log in.

## API reference

All endpoints are mounted under `/api`. Responses share this shape:
```json
{ "error": { "code": "STRING_CODE", "message": "Human message", "details": { /* optional */ } } }
```
on failure, and unwrapped JSON on success. List endpoints return `{ items, pagination }` (offset-based — `page` & `limit` query params).

### Auth
| Method | Path                       | Auth | Body / Query                                            | Notes                                                 |
|--------|----------------------------|------|---------------------------------------------------------|-------------------------------------------------------|
| POST   | `/api/auth/signup`         | —    | `{ email, password, name, university?, major?, gradYear?, role }` | Sends verification email                              |
| POST   | `/api/auth/login`          | —    | `{ email, password }`                                   | Blocked if `emailVerified=false` (configurable)       |
| POST   | `/api/auth/refresh`        | —    | `{ refreshToken }`                                      | Rotates tokens. Reuse-detection revokes the family    |
| POST   | `/api/auth/logout`         | —    | `{ refreshToken }`                                      | Best-effort revoke                                    |
| POST   | `/api/auth/verify-email`   | —    | `{ token }`                                             | From verification email link                          |
| GET    | `/api/auth/me`             | ✓    | —                                                       | Returns full profile (skills, portfolio)              |
| POST   | `/api/auth/google`         | —    | `{ credential }`                                        | **Disabled by default.** Set `GOOGLE_AUTH_ENABLED=true` |

### Users
| Method | Path                     | Auth | Notes                                                                  |
|--------|--------------------------|------|------------------------------------------------------------------------|
| GET    | `/api/users`             | —    | List freelancers; filters: `q, skill, university, role, minRate, maxRate` |
| GET    | `/api/users/:id`         | —    | Public profile + portfolio                                             |
| PATCH  | `/api/users/me`          | ✓    | Update own profile; `skills: string[]` replaces the set                 |

### Jobs
| Method | Path                     | Auth | Notes                                                                  |
|--------|--------------------------|------|------------------------------------------------------------------------|
| GET    | `/api/jobs`              | —    | Filters: `q, category, skill, status, budgetType, minBudget, maxBudget, clientId` |
| GET    | `/api/jobs/:id`          | —    |                                                                        |
| POST   | `/api/jobs`              | ✓    | Creates a job posted by current user                                   |
| PATCH  | `/api/jobs/:id`          | ✓    | Only the client can edit                                               |

### Proposals
| Method | Path                            | Auth | Notes                                                                |
|--------|---------------------------------|------|----------------------------------------------------------------------|
| POST   | `/api/proposals`                | ✓    | Body: `{ jobId, coverLetter, bidAmount }`                            |
| GET    | `/api/proposals/mine`           | ✓    | Proposals you submitted                                              |
| GET    | `/api/proposals?jobId=...`      | ✓    | Proposals **on your job** (client only)                              |
| PATCH  | `/api/proposals/:id`            | ✓    | Freelancer: edit / WITHDRAW · Client: ACCEPT / REJECT (auto-creates Contract, rejects siblings) |

### Uploads
| Method | Path                       | Auth | Notes                                                            |
|--------|----------------------------|------|------------------------------------------------------------------|
| POST   | `/api/uploads/avatar`      | ✓    | `multipart/form-data` — field `file` — JPEG/PNG/WebP/GIF, ≤5MB    |
| POST   | `/api/uploads/portfolio`   | ✓    | Same                                                             |

Static files are served from `/uploads/*` in dev (local driver). In production set `STORAGE_DRIVER=s3` and wire `server/src/lib/storage.ts:S3FileStorage`.

## Database schema

UUIDs everywhere, indexes on foreign keys and commonly queried fields. See `server/prisma/schema.prisma` for the source of truth.

```
┌─────────┐ 1     N ┌──────┐ N     N ┌──────┐ N     1 ┌─────────┐
│  User   │────────►│ Job  │────────►│ Skill│◄────────│  User   │ (UserSkill / JobSkill)
└─────────┘         └──────┘         └──────┘         └─────────┘
     │ 1                │ 1                                  
     │                  │                                    
     │ N                │ N                                  
┌────▼─────┐       ┌────▼─────┐ 1   1 ┌──────────┐ 1   N ┌────────┐
│ Portfolio│       │ Proposal │──────►│ Contract │──────►│ Review │
└──────────┘       └──────────┘       └──────────┘       └────────┘
                                            │
                                            │ between two Users
                                  ┌─────────┴────────┐
                                  │     Message      │
                                  └──────────────────┘
```

### Models
- **User** — `id`(uuid), `email`(unique), `password?`(nullable for Google-only), `authProvider`(LOCAL|GOOGLE), `googleId?`(unique), `name`, `university?`, `major?`, `gradYear?`, `headline?`, `bio?`, `hourlyRate?`, `avatar?`, `role`(HIRE|WORK|BOTH), `emailVerified`, `emailVerificationToken?`, `passwordResetToken?`, timestamps
- **Skill** — `id`, `name`(unique), `slug`(unique). Joined to users via **UserSkill** and to jobs via **JobSkill**
- **PortfolioItem** — `userId`, `imageUrl`, `caption?`, `order`
- **Job** — `clientId`, `title`, `description`, `category`, `budgetType`(FIXED|HOURLY|MONTHLY), `budgetAmount`, `deadline?`, `status`(OPEN|IN_PROGRESS|COMPLETED|CANCELLED)
- **Proposal** — `jobId` + `freelancerId` (unique pair), `coverLetter`, `bidAmount`, `status`(PENDING|ACCEPTED|REJECTED|WITHDRAWN)
- **Contract** — `jobId`(unique), `clientId`, `freelancerId`, `status`(ACTIVE|COMPLETED|CANCELLED)
- **Review** — `contractId`, `fromUserId`, `toUserId` (unique pair `contractId+fromUserId`), `rating`, `comment?`
- **Message** — `fromUserId`, `toUserId`, `content`, `read` *(plumbed for future chat; no UI yet)*
- **RefreshToken** — hashed in DB, rotated on `/refresh`, reuse-detection revokes the whole family

## Auth flow

```
signup ──► server creates User(emailVerified=false) + verification token
        │  └── EmailProvider sends magic link → APP_URL/verify-email?token=...
        ▼
verify-email ──► server marks emailVerified=true
        ▼
login   ──► server checks password + emailVerified → issues access (15m) + refresh (30d)
        │  └── client stores both in localStorage
        ▼
any API call ──► axios attaches `Authorization: Bearer <access>`
        │
        │  on 401:
        ▼
refresh ──► axios POSTs /api/auth/refresh once (serialized)
        │  └── server rotates: old token revoked, new pair returned, retry the request
        │  └── reuse-detection: if a revoked-but-not-yet-rotated token appears, ALL refresh tokens for that user are revoked
        ▼
logout  ──► clears localStorage + POSTs /logout to revoke the refresh token row
```

### Google OAuth (off until you turn it on)

Built into the schema and auth route from day one:
1. **Schema** — `User.password` is nullable, `User.googleId` is an optional unique column. A user can be created via Google with no password.
2. **Endpoint** — `POST /api/auth/google` accepts a Google ID token (`credential`), verifies it via `google-auth-library`, finds-or-creates the user, and returns the same `{ user, accessToken, refreshToken }` shape as `/login`.
3. **Feature flag** — disabled when `GOOGLE_AUTH_ENABLED !== 'true'` (returns 503 with `FEATURE_DISABLED` so the frontend can hide the button).
4. **To enable** — see DEPLOYMENT.md.

## Storage abstraction

`server/src/lib/storage.ts` exports a `FileStorage` interface. Routes call `storage.upload({ buffer, originalName, mimeType, prefix })` and get back `{ key, url, size, mimeType }`. Local writes go to `server/uploads/<prefix>/<random>.<ext>` and are served via Express static at `/uploads/*`. Production swaps the implementation to `S3FileStorage` (placeholder) without route changes.

## Email abstraction

`server/src/lib/email.ts` exports an `EmailProvider` interface. The `console` provider (default in dev) logs to stdout and writes every email as an HTML file under `server/dev-emails/`. The `resend` slot is a stub — install the `resend` package and complete the implementation when you go live.

## What's wired up (and what's not)

✅ **Working end-to-end**
- Signup → verification email (dev console + file) → click link → email verified → login → JWT issued
- `/api/auth/me` populates AuthContext + DashboardNav
- Browse freelancers from Postgres on `/hire`
- Browse jobs on `/work` (filtered to `status=OPEN`)
- Post a job from the dialog on `/hire` (rate-limited, validated, persisted)
- Submit a proposal from `/work` (one-per-job-per-freelancer enforced server-side)
- Profile edit on `/profile` (PATCH `/api/users/me`, skills upsert)
- Token refresh on 401 (serialized, reuse-detection)
- Logout clears localStorage + revokes refresh token

🟡 **Stubbed, not yet implemented**
- Avatar / portfolio upload endpoints exist on the server (`POST /api/uploads/*`) but the profile UI doesn't call them yet
- Reviews / contracts / messages models exist but no UI
- Pagination controls in the UI (server supports `?page=&limit=` already)

🔒 **Behind feature flags**
- Google OAuth (`GOOGLE_AUTH_ENABLED=false`)
- S3/R2 storage (`STORAGE_DRIVER=local`)
- Resend / SendGrid email (`EMAIL_PROVIDER=console`)
